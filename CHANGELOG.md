## [v0.3.0] - 2026-10-11 ([`3bacf2a`](https://github.com/grokify/guardsql/commit/3bacf2a))

### Added

- Built-in SQL compiler (`Compile`) emitting parameterized SQL for SQLite, Postgres, and MySQL from a validated AST, with dialect-specific JSON path extraction on `FieldJSON` columns
- `Config` with `NewUntrustedConfig` and `NewTrustedConfig` trust profiles running parse, validate, policy, and compile in one step
- Field data classification (`ClassPII`, `ClassSecret`) with `Config.AllowPII` and `Config.AllowSecret`; denied fields read as unknown fields
- `IsSafeIdentifier` and `Schema.ValidateIdentifiers` identifier lockdown, on by default and disabled with `AllowUnsafeIdentifiers`
- `Insert`, `Update`, and `Delete` mutation builders with deny-by-default `Field.Writable`, required WHERE, and condition helpers (`Eq`, `In`, `And`, `Or`, `Not`, and others)
- `Config.RowScope`, `ScopeEquals`, and `RequireRowScope` for mandatory tenant/ownership predicates ANDed into every compiled SELECT, UPDATE, and DELETE
- `ClassInternal` data class and `Config.AllowInternal`: internal fields are stripped from the effective schema (reading as unknown fields) unless allowed; off in the untrusted profile, on in the trusted profile
- `FromCatalog` builds a `Schema` from a `datacatalog` catalog, validating it and mapping visibility, PII, and secret tags to the single most restrictive `Field.Class`, with `WithWritable` and `WithNonFilterable` options
- Postgres casts JSON-path extractions to `numeric`/`boolean` for numeric and boolean comparisons and `SUM`/`AVG`, so JSON numeric filters execute
- `CompileOptions.ScopeSchema`: the row-scope predicate resolves against the full schema, so a scope may reference a column hidden from callers
- `Insert` stamps the row scope's equality terms onto the new row, and `Insert`/`Update` reject assignment to scope columns

### Changed

- Minimum Go version raised from 1.23 to 1.25, as required by the new `github.com/grokify/datacatalog` dependency
- JSON path segments are restricted to ASCII letters, digits, and underscore, matching identifier lockdown

## [v0.1.0] - 2026-08-22 ([`d4b4a64`](https://github.com/grokify/guardsql/commit/d4b4a64))

### Highlights

- Initial GuardSQL release with a SaaS-safe parser, AST, schema validation, policy checks, formatter, and in-memory evaluator
- Browser-side TypeScript package and optional SystemForge authorization adapter for application integrations

### Added

- Read-only GuardSQL parser and AST for SELECT/FROM/WHERE/GROUP BY/HAVING/ORDER BY/LIMIT, CTEs, joins, nested sources, aggregate functions, and PRIORITIZE BY ([`0658bf3`](https://github.com/grokify/guardsql/commit/0658bf3))
- Schema validation, static linting, policy checks, query analysis, safe analytics policy defaults, and field requirement extraction ([`0658bf3`](https://github.com/grokify/guardsql/commit/0658bf3))
- In-memory evaluator for single-source filtering, grouping, aggregates, HAVING, ordering, limits, and projection ([`0658bf3`](https://github.com/grokify/guardsql/commit/0658bf3))
- Dependency-free formatter and guardsqlfmt CLI for canonical query output, single-line formatting, and ANSI highlighting ([`0658bf3`](https://github.com/grokify/guardsql/commit/0658bf3))
